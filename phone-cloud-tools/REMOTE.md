# 手机连接自己部署的 Hermes

手机 DSH 0.1.43 提供「服务 → 远程 Hermes」和「设置 → 远程 Hermes」。消息交给另一台机器上的 Hermes 执行；手机显示对话、任务状态与结果，可请求停止，并对服务器提出的操作逐次确认。页面关闭或断网后服务器任务仍可能继续。

已有桌面 DSH 时，可继续用手机顶部「电脑」连接桌面 DSH 来执行远程任务，两端无需在同一 Wi-Fi，详见 [现有电脑连接](../peer/README.md)。Hermes 是可选的另一种 Agent 后端；仅为了远程执行任务无需另部署 Hermes。云端发行 ZIP 内不含上述电脑文档，可在项目仓库查看。

这是自部署 Hermes 的客户端入口。发行包不含 Hermes 本体、模型账号或已开通的服务器；需要一台持续运行 Hermes 的电脑或服务器，以及自己的模型配置。当前实现已通过本地 HTTP 协议与断线测试，正式 Hermes 模型、公网 TLS 和跨设备联调需要在实际服务器上验收。

## Jet Hub、Hermes 与跨网络使用

Jet Hub 负责把模型请求转给模型供应商。DSH 使用 Jet Hub 时，DSH 在手机上使用工具、执行任务；远程 Hermes 则在其所在电脑或服务器上使用工具、执行任务。Hermes 也可以使用兼容的 Jet Hub 模型接口，但需由 Hermes 所在机器访问得到该接口，并单独配置模型地址、模型名与模型凭据。

手机和 Hermes 不需要在同一局域网。出门使用手机流量也可以访问 HTTPS 服务或通过私有组网访问有效的 HTTPS 地址。家里电脑仍需开机并运行 Hermes；内网地址不能直接从外面访问。手机里的 `127.0.0.1:8326` 只指手机本机，服务器不能直接拿这个地址访问手机 Jet Hub。现有 DSH 电脑配对不自动成为 Hermes 的模型接口。

本页面要求非回环地址使用 HTTPS，并验证系统信任的证书；仅 `localhost`、`127.0.0.1`、`[::1]` 允许 HTTP 用于本机测试。普通局域网 HTTP 地址与未受信自签证书不能直接使用。

## 服务器准备

1. 在自己的机器上安装并配置 Hermes，先从 Hermes 原有入口验证模型可以正常回答和执行预期任务。模型选择、API 地址及账号在服务器配置，参考 [官方供应商说明](https://hermes-agent.nousresearch.com/docs/integrations/providers/)。不需要因使用这个手机入口而开通 Nous Portal 订阅。
2. 使用支持 `/v1/capabilities`、`/v1/runs`、任务查询、停止与确认的 Hermes API Server。手机会先检查接口能力，旧版本不满足时提示升级，不会把普通模型网关误认作 Hermes。
3. 将 0.2.1 通用接入包解压到服务器上的专用目录。需要 Node 22 以上，推荐 Node 24。发行包已经附带手机工具连接器的依赖。
4. 对已配置好模型的默认 Hermes 目录运行：

   ```sh
   cd /opt/dsh-phone-tools
   node bin/enable-api.mjs "$HOME/.hermes"
   hermes gateway
   ```

   辅助脚本仅修改 `.env` 的 `API_SERVER_ENABLED/HOST/PORT/KEY`，把 API 绑定到 `127.0.0.1:8642`；保留模型配置和其他环境变量，并将已有 `.env` 备份为同目录的 `.env.before-dsh-phone-*`，权限 600。已有合格连接密钥复用，没有或过短时生成新的随机密钥。脚本不打印密钥、不启动 Hermes。已有 gateway 需要由管理者重启。使用专用 profile 时，应传该 profile 的绝对目录，并通过 Hermes 对应的 profile 入口启动；配置与启动的 profile 必须一致。
5. 用实际域名、有效证书与 HTTPS 反向代理公开这个专用 API，参照 `nginx-hermes.example.conf`。不要直接公开无鉴权的 8642 端口。该示例代理 `/v1/`；如需 Hermes 的 `/p/你的profile/v1/` 路径，按自己的实际 profile 代理，仅开放需要的 profile。手机工具中继使用另一份 `nginx-relay.example.conf`，二者不能直接用同一域名的重复 server 块。

API 配置与模型凭据属于不同部分，见 [Hermes 官方 API Server](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server)。使用其他机器上的 Jet Hub 时，Hermes 配置中的模型接口必须指向该机器可达的地址；会员授权与模型权益仍受供应商接口支持范围约束。

## 手机填写三项

1. 打开「服务 → 远程 Hermes」，连接名称随意填写，例如「家里的 Hermes」。
2. 「Hermes API 地址」填 `https://hermes.example.com`；专用 profile 可填 `https://hermes.example.com/p/phone`。末尾 `/v1` 会自动处理。地址里不放用户名、密码或查询参数。
3. 「连接密钥」填服务器 `.env` 的 `API_SERVER_KEY`。在自己的私有终端或密码管理器读取，勿贴到公开聊天、仓库或截图。这不是 Jet Hub、DeepSeek 或其他模型的 API Key。

点击「保存连接 → 检查连接 → 新建对话」，再输入任务。检查连接只查询服务能力，不调用模型。发送会使用该 Hermes profile 当前配置的模型；手机不上传现有 DSH 会话、角色卡、模型密钥或 QQ 消息。实际模型由服务器在任务结果中提供时显示。

界面只显示连接密钥是否已保存，不回显。相同地址留空可保留原密钥；换地址需填写新密钥。有未结束或提交结果未知的任务时，先在原服务器核对，避免改连接后丢失任务控制。移除连接只忘记本机密钥，不等于停止服务器任务。

## 手机工具是另一条连接

| 信息 | 配在哪里 | 用途 |
|---|---|---|
| Hermes API 地址与 `API_SERVER_KEY` | 手机「远程 Hermes」 | 手机向 Hermes 交代任务 |
| 模型地址、模型名、模型凭据 | 服务器 Hermes | Hermes 调用你选择的模型或模型网关 |
| 加密中继地址与手机配对信息 | 手机「手机工具箱」和服务器 MCP 连接器 | Hermes 请求手机技能和工具 |

需要 Hermes 使用手机工具时，继续按 [工具集接入说明](README.md) 完成独立配对、共享范围与手机批准。仅连接远程聊天不自动启用手机工具。服务器终端和文件工具默认作用于服务器；手机操作由 `phone_*` 工具提出，再由手机本人确认。

## 断线、确认与停止

- 每次发送先在手机记录原消息和唯一请求编号；提交后用服务器任务编号查询，不自动重发。服务器已接收但手机没收到回执时，显示「提交结果未知」。只有原服务器明确支持持久去重且仍在保留期内，才能由本人确认恢复原任务编号。不要换新编号自动重跑；服务器状态库被清空时先到服务器核对。
- 服务器操作确认只开放「这一次」与「拒绝」，绑定服务器返回的具体请求编号，提交前重新核对内容。服务器没有提供编号时请在 Hermes 原有入口确认。手机工具授权独立保留。
- 「停止任务」请求 Hermes 停止，显示正在停止，直到服务器确认结束。已完成的文件写入等副作用不会自动撤销。
- 本机最多保存 50 段对话、每段 400 条消息，总文件上限 8 MiB。单条发送最多 32 KiB；服务器响应读取上限 1 MiB。达到限制时先备份整理，或去 Hermes 原入口查看。对话记录在手机独立 `hermes-remote/conversations.json` 中，覆盖升级保留。
- 鉴权失败检查 API key 与 profile 是否匹配；404 检查版本、地址与代理路径；TLS 或连接失败先检查网络、证书和服务状态。手机拒绝 HTTP 重定向，避免将密钥转给另一服务，填写最终 HTTPS 地址。
