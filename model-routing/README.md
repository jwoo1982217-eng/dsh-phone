# DSH 模型路由组 0.2.0

入口：设置 → 模型 → 模型路由组。新建组，搜索并添加已配置的模型，再选策略。保存后，回到聊天的模型列表，选“模型路由组”分组中的组名。

- 智能：给成员指定强模型/省钱模型，默认用本地规则判断；可显式选择分类模型（会额外发送当前任务片段并可能收费）。
- 按顺序：按成员位置使用，首次输出前遇到可重试故障切换。已经有正文、思考或工具调用时不重放请求。
- 轮流：每次请求轮换。最少使用：优先本机调用次数较少的成员。
- 按权重：按填写的比例分配。手动：固定选定成员，不做故障分流。
- 重置前用完：根据手工填写的剩余请求次数、重置时间和周期分配；成功一次扣一次。不会猜测厂商额度，也不读取账号余额。

可以配置：限流后顺序、首次输出等待、全部成员忙时等待、上下文容量、会话保持、成员单独展示、按供应商/模型 ID 通配匹配。最后一个成员不受首次输出超时限制；用户仍可随时取消。

配置在当前 `DSH_HOME/model-routing/settings.json`，使用统计在 `runtime.json`。保存检查配置版本，避免两个页面互相覆盖。诊断保留最近 50 次选择和固定错误分类，不记录问题正文或原始上游错误。

桌面与 Android 使用同一份插件源码，分别由各自固定的 SDK 运行。模型账号和路由组保留在本设备，不自动复制到其他设备。

验证：`node --test tests/routing.test.mjs`；可用 `DSH_SDK_MODULES` 指向另一端的固定 SDK `node_modules`。验收使用本机夹具，不向付费模型发请求。SDK 测试不能替代安装后的页面和真实执行链路验收。
