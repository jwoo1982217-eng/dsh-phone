# 手机 QQ 配置导入

APK 顶部「导入配置」打开 `/phone-import`。支持选择 JSON 文件、粘贴或直接填表。
检查会显示机器人号码、管理员、地址和模型。点击「保存导入」后默认停止，
再由使用者点击「启动机器人」。已启用的配置会在 App 重启时恢复连接。

每个安装都是空白 QQ 配置，各自通过「DeepSeek 账号」或 Jet Hub 登录自己的模型账号。
QQ 配置单独保存在手机 credentials 服务中。状态和导出不会返回 OneBot 令牌。
导出的 JSON 可复制到另一台手机；新设备单独补填令牌。配置最大 32 KB。

`qq-config-template.json` 的机器人和管理员字段须替换为自己的号码。
模型 `provider` 和 `model` 两个字段均为 null 时跟随 DSH 默认模型，
也可指定已登录的 `deepseek-account` / `deepseek-flash`。

OneBot 的正向 WebSocket 服务应提供 API 调用和事件推送；APK 连接其地址。
反向模式由 APK 监听本机端口，NapCat 连接 APK；填 `ws://127.0.0.1:8082`
仅在本机监听，填 `ws://0.0.0.0:8082` 允许局域网连接且必须提供令牌。
群聊默认要求 @机器人，随机插话默认关闭、主动定时任务关闭，语音转写默认关闭。

APK 没有内置 Linux 环境或 NapCat 的 QQ 登录程序。QQ 在其他设备上登录时仍依赖
该设备；完全独立运行需要在手机上另行运行兼容的 OneBot 服务。手机的 Android
后台限制也会影响持续连接。文字机器人传输与启停已用本地模拟 OneBot 验证，
实际 QQ 收发、原插件音乐/语音/原生工具需要相应后端与环境，不能视为已通过真机测试。

已有 Mac 配置可以通过项目脚本生成 JSON：

```sh
node scripts/export-qq-config.mjs "$HOME/.dsh/profiles/web/cordis.patch.yml" ./my-qq.json
```

只迁移连接、QQ 号码、管理员、主群、群聊触发、模型选择与称呼；不迁移旧聊天、
DeepSeek 授权或 Mac 工作区路径。需要同时迁移 OneBot 令牌时显式加 `--include-token`，
该个人文件不要放进 APK 资源或发给其他使用者。脚本不会覆盖已有输出。


## ZIP 技能库与提示卡（0.1.6）

从机器人首页进入「技能包 · 提示卡 · 运行增强」。ZIP 导入会检查文件大小、CRC、路径及重复项，保留技能引用的脚本和参考资料；模型加载时能获得真实资源目录。导入不执行安装器。可搜索技能、查看指令，停用单项或整包。自定义方法也可在手机聊天和 QQ 工作区发现。

0.1.33 起，普通 DSH 主 Agent 在「设置 → Agent 人设」管理主卡、副卡与组合；既有提示卡的正文和启用状态会迁移到副卡库。原提示卡编辑器继续用于 QQ（同时最多 4 张），不改写会话历史。详细说明见 [Agent 主副人设卡](../peer/agent-cards/README.md)。

运行增强有 3 个兼容项：命令超时、大文件阅读和子任务深度；默认开启前两项。先保存，再点击「重启手机 DSH 服务」生效。对源文件做匹配检查、语法验证和备份，不匹配时保留原文件。原始 40 个桌面补丁的状态可展开查看；全局审批和文件围栏改写未应用，QQ 群聊与其他用户权限保持原设置。

安装登录端后，在「连接」页直接查看二维码，或点顶部「QQ 扫码登录」定位。二维码过期可刷新。机器人 QQ 在另一部手机时，直接用那部手机的 QQ 扫描 DSH 显示的二维码并确认。同一台手机先截图，再用机器人那个 QQ 号的「扫一扫 → 相册」选截图并确认。回到 DSH 后点击「连接机器人」。仅安装登录端不等于 QQ 账号已登录；高级管理页保留供额外验证或排查。

普通中文 Markdown 可作为方法或角色卡攻略导入，自动读取标题与「用途」，生成稳定的调用标识并保留原文。显示名称支持中文；标准 SKILL.md 仍可使用原有英文标识。导入后先检查表单，再点击保存并启用；这会增加可按任务调用的技能，不会自动替换机器人的常驻性格。

「启动／恢复 QQ 登录端」可直接重启本机登录服务并同步当前令牌，保留 QQ 环境与账号文件。启动会清理同一 dsh-qq 容器的残留进程并等待旧端口退出；重试同一 QQ 账号保留原令牌，避免旧进程与新令牌不一致。

恢复登录端只重启专用 dsh-qq 容器，保留已有 QQ 配置。PRoot 忽略 SIGTERM，使用 SIGQUIT 触发 tracee 清理，等待旧端口关闭后才启动新实例。

点击刷新会显示生成进度与成功更新时间；遇到正在读取状态的轮询，会排队生成新二维码，不会丢弃点击。
