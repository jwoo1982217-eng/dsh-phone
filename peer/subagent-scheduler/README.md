# 子代理调度

DSH 0.2.1-alpha.1：主模型根据子任务内容，从已配置的精确 provider/model 候选中选择，再调用原生 subagent/subagent_fork。工作标签是用户偏好，不是能力测试结果。默认不发额外模型探针。漏选线路时，支持原生模型选择的聊天会收到补选提示；固定线路的旧聊天保留 SDK 行为，建议新建聊天。

设置 → 子代理调度：按供应商折叠展示当前宿主完整模型目录，包含自行配置的正规 API；支持搜索、供应商快速跳转和独立滚动。展开供应商后加入候选并勾选工作类型。保存只授权精确选中的线路，新增授权供新聊天使用，已有聊天的持久授权不变。同一来源的模型共用额度组；不同来源若共用账号限额，也应使用同名额度组。初始只使用已授权的 DeepSeek 官方 Flash/Pro；未配置其他候选时不会擅自调用目录里的其他接口。

总开关“允许子代理协作”控制新建与向既有子代理派发后续任务；关闭时保留已接收任务完成及子代理向父代理回报。请求排队开关独立控制并发保护。

默认总并发 2、每额度组 1、每模型 1、同组请求间隔 1000ms。统一 llm/stream 队列同时覆盖主模型和子代理；RATE_LIMIT 终止回执会使同组后续请求冷却 30 秒。取消排队不会调用上游；已经输出内容或执行过工具的失败请求不会自动重放。不同模型可能共用限额，队列不能保证消除所有 RPM、Token 或账号余额限制。

原生线路在创建前固定，复用和冷启动沿用原子代理模型；不修改已准备的 LLM 请求，不更改 SDK 文件。配置原子保存在 DSH_HOME/storage/subagent-scheduler/config.json，修改候选/额度组须等待现有队列完成。后台任务监督器的新计划也由主模型逐节点指定 provider/model；已有探针和预算规则保留。

验证：scheduler.test.mjs 检查共享额度、总量、间隔、取消、限流和卸载恢复；native.test.mjs 用固定 SDK 的真实工具与本地模型夹具验证主模型派给两个不同模型；scripts/subagent-scheduler.e2e.mjs 检查真实服务、可持续子代理复用及重启恢复、设置保存与布局。测试不代表真实云模型的语义选择质量或扣费行为已验收。
