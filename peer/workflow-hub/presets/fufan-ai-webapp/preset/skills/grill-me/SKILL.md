# 产品决策访谈

本 Skill 从 `mattpocock/skills` 的 `grill-me` 与 `grilling` 改造而来，固定上游提交为 `068b6e0c62393147daf03530149cdce209c93da8`。本版本把上游隐藏依赖内联，并改用 DeepSeek Harness 的正式交互和文件工具。许可证见 `LICENSE.txt`。

## 目标

在写规格或代码前，把产品方案展开成一棵决策树。只向用户询问真正需要其决定的事项；环境事实由你使用文件、搜索或 Shell 工具自行核对。

## 执行规则

1. 先读取仓库 `AGENTS.md`、`CONTEXT.md`、现有规格和相关实现，列出已确定事实。
2. 建立决策树：每项决策只依赖其上游已经确定的决策。
3. 每轮只询问当前“决策前沿”，即现在就能回答且不依赖未决问题的事项。
4. 每轮最多三个问题；每题必须编号、说明影响并给出推荐答案。
5. 可以从仓库或工具查到的事实不得反问用户。先使用 `read`、文件搜索或 `bash` 核验，再继续决策树。
6. 用户回答后重算决策前沿，不得按预先准备的问题清单机械追问。
7. 决策前沿为空后，输出“共同理解摘要”：目标、最终成果、用户把控点、明确不做的内容、验收标准。
8. 未得到用户明确确认前，不写规格、不改产品代码。

问题格式：

```markdown
❓ Q1｜问题标题

问题正文与互斥选项。

➡️ 推荐：推荐答案及理由。
```

## 完成条件

- 所有仍会改变产品范围或最终形态的分支均已确定。
- 可查事实已由工具核验，没有推给用户。
- 用户明确回复共同理解正确，可以进入规格阶段。

只输出决策结果和待确认事项，不把访谈包装成已经完成的实现。
