# 好测试与坏测试

## 好测试

好测试通过真实公开接口验证用户关心的行为。例如网页功能从浏览器点击开始，最后断言用户看见的状态、下载文件或错误反馈。

```javascript
test("点击更新数据后页面应用固定 JSON", async ({ page }) => {
  await page.goto(projectUrl);
  await page.getByRole("button", { name: "更新数据" }).click();
  await expect(page.locator("html")).toHaveAttribute("data-palette", "mint");
});
```

特征：

- 测试用户或调用方关心的结果。
- 使用公开接口，内部重构后仍然成立。
- 测试名称描述“是什么”，不是“怎样实现”。
- 每个测试只覆盖一个逻辑行为。
- 期望值来自规格中的独立字面量。

## 坏测试

以下做法会让测试和内部实现绑定：

- Mock 内部协作者并断言调用次数或顺序。
- 直接调用私有函数或读取内部变量。
- 绕过公开接口查询旁路状态。
- 用与实现相同的算法重新计算期望值。
- 一个测试同时验证多个不相关功能。
- 只检查元素存在，却没有执行用户行为。

浏览器产品优先使用真实点击、键盘、拖拽、网络请求、可见文本、下载和控制台作为观察点。
