# 按需工具与技能

该插件通过 SDK 的 `system-prompt/assemble` 扩展裁剪每次请求中的工具定义。完整工具仍注册在原执行器中，权限、参数校验、执行回调与会话记录保持原有机制。

新任务常驻 `tool_search`、`tool_load`、`skill`、`read` 和询问入口。模型根据任务检索简短目录，用 `tool_load` 加载最多 8 个精确名称；完整参数在下一次请求出现。无需用户报出工具或技能名称。加载仅作用于当前 Agent 当前任务，任务结束收回；子 Agent 独立检索加载。当前作用域的结构化输出工具始终可用。

显式工具白名单的子代理若没有获准使用发现入口，直接保留其原有许可清单，防止隐藏它仅有的读取工具。插件不为它添加入口或放宽原权限。

已加载定义共用 24,000 JSON 字符预算，超出时收回较旧定义。这个数是本地展示预算，不代表任何供应商的上下文或免费额度。拒绝无效、超大或未授权批次时，旧选择保持。原生工具、TypeScript PTC、Python PTC 和双模式均适用。

技能继续使用 SDK 的 `skill` 工具按需读正文，标准、PTC 和 Cordis 预设中的目录简介上限为 160 字符。技能正文、脚本和参考文件无需删减。

插件由 `dsh-peer/cordis.patch.yml` 的独立条目加载，可单独卸载恢复原请求展示，无需重启或重连 MCP。两端安装器、手机资源打包均包含本模块。

旧会话积累的历史、人格正文及上游账户资格限制仍会影响模型可用性。工具展示优化不会自动清除历史或改变账户资格。
