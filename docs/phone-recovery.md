# 手机插件备份与恢复

入口是手机顶部原生 **服务 → 备份与恢复**，无需 DSH 网页正常启动。在「电脑」模式下，此入口仍管理手机本机环境。

1. 安装或更新插件前，先等待手机上的 AI 任务结束。
2. 点「快速备份」，确认后本机服务短暂停止，保存成功后自动重新启动。等待显示「备份完成」再安装插件。
3. 如果插件导致启动失败，打开同一入口，选择「恢复最近备份」。也可选择「恢复较早备份」，窗口会显示每份备份的时间、应用版本和大小。
4. 恢复前会校验备份并保存当前环境。恢复成功后重启本机 DSH；如需返回恢复前的环境，点「撤销上次恢复」。
5. 已知是额外插件出错时，点「禁用社区插件」，选择要停用的项。确认后先备份，再禁用并重启；内置核心功能受保护。profile 无法解析时直接恢复备份。

这是**插件和运行环境的回滚**，不会降级 APK。备份包括应用内程序树、DSH profiles（插件目录及配置）、home 依赖目录或链接、settings.yaml 和运行资源标记。会话、附件、凭据、Agent 人设卡、设备配对、Noema 记忆、用户技能及工作区资料不在替换范围，保留恢复时的最新内容。提供商、默认模型等 settings/profile 配置会恢复到备份时的值。外部 Termux／NapCat 环境、其他应用、插件指向应用外部的依赖及原生 APK 程序不由此功能回滚。

保留最近两份手动备份，以及一份恢复前环境用于撤销。插件更新不会自动创建备份，请先使用「快速备份」。备份保存在应用私有目录，配置中可能包含个人信息，不上传云端、不复制到下载目录；卸载应用或清除应用数据会删除备份。APK 覆盖升级保留备份，但原生运行库或 DSH 核心发生不兼容变化时会拒绝恢复。

有运行中的 AI 任务时操作会被阻止。网页已崩溃而无法读取任务状态时，原生确认窗口会说明操作将停止服务。空间不足、校验失败或服务没有安全退出时不会替换运行环境。替换使用恢复日志；应用在替换过程中被终止，下次启动会先回到完整的原环境。

开发验证：`python3 scripts/test-android-recovery.py --serial YOUR_DEVICE --adb /path/to/adb` 在单独的临时应用 UID 内测试，不停止、替换或读取正式 DSH 的数据。

从 0.1.36 起，市场「允许试装」在原生确认后自动执行：等待本机 AI 任务结束 → 停止服务 → 保存最近备份 → 安装固定发布包 → 重启服务。下载或依赖安装失败会恢复这份备份；插件启用后出现启动/界面异常，可以手动恢复最近备份。试装不保证第三方插件可运行，也不会隔离其对账号和文件的访问。
